NDRRS Platform

National Disaster Response & Rescue System

Evaluation Round 2: Architecture, Modules & Execution

1. System Architecture: Tech Stack

  • Frontend: React.js & Vite for optimized builds
  • UI/UX: Modern Glassmorphism for mobile
  • GIS Mapping: Leaflet.js with custom CSS divIcon
  • Hosting: Vercel Global Edge Network

How the System Works: Real-Time Data Flow

  • A citizen presses the Emergency button on the mobile application.
  • The device automatically collects:
    • Current GPS location
    • Battery percentage
    • Network status
    • Current date and time
  • This information is instantly sent to the cloud using MQTT WebSockets.
  • The Admin Command Center immediately receives the alert.
  • The victim's location appears on the live disaster map within milliseconds, allowing rescue teams to respond quickly.

Key Benefit: The entire process happens in real time with extremely low latency, helping save valuable time during emergencies.

Module A: Citizen Portal

  • Objective: Stress-free, 0-second SOS trigger.
  • Features: Ultra-minimalist UI with 1-click EMERGENCY/SAFE buttons.
  • Under the Hood: Persistent localStorage identity to prevent spam. Geographic scattering algorithm to prevent stacking.

Module B: Admin Command Portal

  • Objective: God's-eye view of disaster zone for NDRF.
  • Features: Live map, breathing red dots, real-time audio sirens.
  • Under the Hood: React Context API dynamic coordinates updating without full page reloads.

Module C: Cloud Sync Engine

  • Objective: Guarantee transmission on poor 4G/5G.
  • Features: Industrial MQTT Pub-Sub over WebSockets.
  • Advantage: Exact same engine used by WhatsApp. Syncs 15+ phones to laptops in under 50ms with zero CORS blockers.
